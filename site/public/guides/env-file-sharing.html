.envファイルをチームで共有する方法｜Gitとチャットに平文で置かない

平文の.envを、Gitとチャットに置かないでください。
渡し方は、人数と続ける期間で選びます。

内容の確認日: 2026年11月5日

結論

  • 平文の.envは.gitignoreに入れます。どの変数が要るかは.env.exampleで伝えます。
  • 新しい人に1回渡すだけなら、1回だけ読めるリンクで足ります。
  • チームで続けて使うなら、暗号化してGitに入れる（dotenvx、SOPS）か、管理ツール（1Password、Doppler、Infisical）を使います。
  • Gitに入れてしまったら、消す前にキーを止めます。

リンクを作る ›

まず、Gitに入らないようにする

GitHubのNode向けの.gitignoreのひな形は、次の形です。

# dotenv environment variable files
.env
.env.*
!.env.example

すでにGitが追跡しているファイルは、.gitignoreに書いても外れません。先に追跡をやめます。

git rm --cached FILENAME

どの変数が要るかは、値を消した.env.exampleで共有します。
Laravelの文書も、チームならこの形をすすめています。

# .env.example
STRIPE_KEY=
DATABASE_URL=

Twelve-Factor Appの目安も分かりやすいです。
認証情報を漏洩させることなく、コードベースを今すぐにでもオープンソースにすることができるかどうかを考えます。

決まりは、ファイルの名前ではなく秘密についてのものです。
開発用の値だけのファイルをコミットする考え方もあります（Rubyのdotenv）。
本物のキーが入るなら、入れないでください。

どの方法を選ぶか

方法向いている場面別に渡すもの
1回だけ読めるリンク新しい人に1回渡す。外部の人に渡す合言葉を付けるならそれ
dotenvxコードと一緒にGitで管理したい秘密鍵（.env.keys）
SOPSKMSやageで人ごとに権限を分けたい共有の鍵は要りません。各人の公開鍵を受取人に足します
1Password Environmentsチームで1Passwordを使っているなし（1Passwordの中で共有します）
Doppler、Infisical環境ごとの秘密を1か所で管理したいなし（ログインして取り出します）

暗号化してGitに入れる

「Gitに入れない」のは平文の話です。
暗号化してあれば入れてよい、という考え方もあります。

dotenvx

dotenvの作者によるツールで、dotenvのREADMEも、dotenvxで暗号化するならコミットをすすめています（作者自身の製品です）。

dotenvx encrypt
git add .env
git commit -m "encrypt .env"
dotenvx run -- node index.js
  • 秘密鍵は.env.keysに入ります。これはコミットしません。
  • .envを.gitignoreに入れたままなら、追加はgit add -f .envになります。
  • 秘密鍵は、必要な人とサーバーへ別に渡します。
    dotenvxの文書は、どう渡すかまでは書いていません。1回だけ読めるリンクが使える場面です。
  • 変数名は読めます。コメントも暗号化されません。

SOPS

YAML、JSON、ENV、INIなどを暗号化するツールです。
AWS KMS、GCP KMS、Azure Key Vault、age、PGPなどで暗号化します。CNCFのSandboxプロジェクトです。

age-keygen -o key.txt
sops encrypt --age age1yt3tfqlfrwdwx0z0ynwplcr6qxcxfaqycuprpmy89nr83ltx74tqdpszlw test.yaml > test.enc.yaml
sops edit mynewtestfile.yaml

上は文書にある例で、YAMLの場合です。age1...は受取人の公開鍵に置き換えます。
各人が自分の鍵で開くので、共有の鍵を配らずに済みます。
こちらも変数名は読めます。

管理ツールを使う

1Password Environments

2026年8月のお知らせで一般提供になりました。
オーナーか管理者がポリシーを有効にすると、チームで共有できます。
MacとLinuxでは.envとして見せる機能があり、中身はディスクに保存されません。
Windowsではop run --environmentを使います。

Doppler

コマンドで環境変数として渡すサービスです。
3人まで無料で、それ以上は1人あたり月8ドルです（2026年11月5日時点）。

doppler login
doppler setup
doppler run -- your-command-here

Infisical

オープンソースの管理ツールで、自分のサーバーでも動かせます。
無料プランは5つのID（人と機械を合わせて）までです。リンクで秘密を共有する機能もあります。

1回だけ読めるリンクで渡す

準備なしで使えるのが利点です。
新しい人に.envを1回渡す場面に向いています。
チームの全員に繰り返し配るなら、上の方法のほうが向いています。

  1. トップページで.envを選ぶか、枠の中にドラッグします（64KBまで）。
  2. 有効期限を選び、必要なら合言葉を入れます。
  3. 「リンクを作る」を押して、相手に送ります。

ファイルの名前も中身と一緒に暗号化します。サーバーには名前も届きません。

受け取る人へ:ブラウザで保存すると、.envの先頭の点が外れてenvになります（Chromium、WebKit、Firefoxで確かめました）。
使う前に元の名前に戻してください。

Gitに入れてしまったら

消す前に、中のキーを止めます。
GitHubは、秘密が漏れたときの最初の手順は無効化か入れ替えだと書いています。

ファイルを消すだけでは足りません。
GitHubの文書にあるとおり、消したファイルも履歴には残ります。
直前のコミットでまだプッシュしていないなら、取り消して済みます。それより前なら履歴の書き換えが要ります。

手順はAPIキーが漏れたときにやることに書きました。
